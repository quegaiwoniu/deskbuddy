# DeskBuddy 使用手册

## 安装与基本操作

打开 DMG，将 DeskBuddy 拖入「应用程序」目录后启动。当前已验证 macOS Apple Silicon；Windows 10/11 x64 已完成基础适配（NSIS 安装包）。

| 操作 | 效果 |
|---|---|
| 鼠标靠近角色 | 触发配置的悬停动作 |
| 按住拖动 | 移动角色位置 |
| 右键角色 | 打开动作、设置、隐藏和退出菜单 |
| 托盘菜单 | 显示或隐藏桌伴、切换角色、打开设置 |

## 陪伴与角色

在设置 → **陪伴** 中管理角色。应用默认不预置角色，可通过一张图片创建、生成动画草稿或导入角色包添加。

- **使用一张图片**：填写角色名称，选择 PNG、WebP 或 JPEG，创建带程序化动效的静态图角色。
- **生成动画草稿**：填写名称和描述，应用生成 `PROMPTS.md` 与素材目录；使用你选择的图像生成工具制作素材，再通过「继续制作」检查并组装。
- **导入角色包**：选择包含 `pet.json` 的角色根文件夹（例如 `xiaobao`），不要选择 `frames` 子目录。ZIP 请先解压。应用按角色配置检查并只复制运行所需的图片或连续动作帧；制作记录、预览 GIF/视频和其他无关文件不会导入。

GIF 拆帧由应用内置的 Rust 解码器完成，无需安装 Swift 或外部工具。

自行导入的外部角色保存在 `~/.config/deskbuddy/pets/`。不要将私人照片、生成记录或未经授权的素材放入公开发布包。

角色包格式见 [资源说明](../assets/pets/README.md)。

## 编码工具接入

应用会跟踪支持的 Codex 与 ZCode 本地会话记录，显示会话名称及近期内容。记录路径与格式变化可能影响识别。

Codex 完成通知也可通过适配器接入。在自己的 Codex 配置文件 `~/.codex/config.toml` 中配置：

```toml
notify = ["bash", "/path/to/deskbuddy/adapters/codex-notify.sh"]
```

将示例路径替换为源码中的真实脚本路径。若已有通知程序，可用 `DESKBUDDY_FORWARD_BIN` 指定转发目标；用 `DESKBUDDY_BIN` 指定 DeskBuddy 命令行程序路径。

Git 提交事件接入：

```sh
bash /path/to/deskbuddy/adapters/install-git-hook.sh /path/to/your-repo
```

## 通知

通知展示会话名称和内容，并区分处理中、完成、失败和需要确认。结束通知会根据来源应用是否处于前台决定是否显示；切回来源应用时可清除未读通知。实时工作状态持续展示。

## 设置

| 栏目 | 内容 |
|---|---|
| 陪伴 | 添加、导入、制作、切换和删除角色 |
| 行为 | 轮播间隔、动作权重、悬停行为 |
| 通知 | 事件反应、提示音与气泡显示 |
| 启动与显示 | 开机自启、位置重置、窗口层级 |
| 关于 | 应用信息 |

行为与事件配置说明见 [配置文档](configuration.md)。

## 命令行

安装版可通过 `/Applications/DeskBuddy.app/Contents/MacOS/deskbuddy` 调用，或将该程序加入 PATH。Windows 安装版程序位于 `%LOCALAPPDATA%\DeskBuddy\deskbuddy.exe`（NSIS currentUser 模式）。

```sh
deskbuddy emit task.completed --title "任务完成"
deskbuddy emit task.failed --title "测试失败"
deskbuddy play waving
deskbuddy say "休息一下"
deskbuddy pet <角色ID>
deskbuddy settings
deskbuddy status
```

## 本地数据与排查

配置、外部素材及日志保存在 `~/.config/deskbuddy/`。角色不见时，可从托盘菜单选择「显示桌伴」，或在设置中重置窗口位置。

应用事件服务器只监听本机回环地址。它会处理本地会话文本，运行日志可能包含消息内容和文件路径；共享日志前请检查并移除这些信息。第三方图像生成工具的数据处理方式由该工具决定。
